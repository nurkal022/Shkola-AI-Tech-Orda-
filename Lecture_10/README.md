# Лекция 10: Продвинутый поиск с Hybrid Search и RRF

## 📋 Содержание лекции

## 🎯 Ключевые концепции

### BM25 (Best Matching 25)

**Формула:**
```
score(D, Q) = Σ IDF(qi) × (tf × (k1 + 1)) / (tf + k1 × (1 - b + b × |D|/avgdl))
```

**Плюсы:**
- ✅ Быстрый (не требует ML)
- ✅ Точные совпадения
- ✅ Учитывает редкость слов

**Минусы:**
- ❌ Не понимает синонимы
- ❌ Не понимает контекст

---

### Semantic Search

**Как работает:**
1. Текст → Эмбеддинг (вектор 1536D)
2. Запрос → Эмбеддинг
3. Поиск по косинусному сходству

**Плюсы:**
- ✅ Понимает синонимы
- ✅ Понимает контекст
- ✅ Работает с парафразами

**Минусы:**
- ❌ Может "улетать" по смыслу
- ❌ Требует ML модель
- ❌ Дороже и медленнее

---

### Hybrid Search

**Формула:**
```
hybrid_score = (1 - α) × normalize(BM25) + α × normalize(Semantic)
```

Где `α ∈ [0, 1]` - вес Semantic Search (рекомендуется 0.3-0.5)

**Архитектура:**
```
Запрос
  ├─→ BM25 Search → Scores
  └─→ Semantic Search → Scores
         ↓
    Normalization (0-1)
         ↓
    Weighted Sum
         ↓
    Top-K Results
```

**Плюсы:**
- ✅ Объединяет лучшие стороны обоих методов
- ✅ Настраиваемый баланс (α)
- ✅ Лучшее качество чем каждый метод отдельно

---

### RRF (Reciprocal Rank Fusion)

**Проблема:** Scores от разных источников несопоставимы

**Решение:** Использовать только **ранги**, не scores!

**Формула:**
```
RRF_score(d) = Σ 1 / (k + rank_i(d))
```

Где:
- `k = 60` (константа сглаживания)
- `rank_i(d)` = позиция документа в i-м поиске

**Пример:**
- Документ A: BM25 rank=1, Semantic rank=5
  - RRF(A) = 1/(60+1) + 1/(60+5) = 0.0318
- Документ B: BM25 rank=10, Semantic rank=2
  - RRF(B) = 1/(60+10) + 1/(60+2) = 0.0304
- **Результат:** A > B (A стабильно в топе)

**Плюсы:**
- ✅ Не требует нормализации
- ✅ Работает с любым количеством источников
- ✅ Устойчив к выбросам

## 💡 Рекомендации

### Когда использовать BM25:
- Быстрый прототип
- Точные совпадения важны
- Нет бюджета на embeddings
- Простые запросы

### Когда использовать Semantic:
- Синонимы критичны
- Пользователи задают вопросы по-разному
- Нужен контекстный поиск
- Есть бюджет на embeddings

### Когда использовать Hybrid:
- Нужен баланс точности и понимания
- Есть оба индекса
- Качество поиска критично
- Можно настраивать α

### Когда использовать RRF:
- Много источников поиска (>2)
- Scores несопоставимы
- Нужна простота объединения
- Устойчивость к выбросам

### Оптимальная конфигурация:
```
BM25 + Semantic + RRF
→ Лучшее качество на практике
→ Устойчивость к выбросам
→ Работает с любым количеством источников
```
